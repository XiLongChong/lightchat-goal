> 基准：`11/v1.3/goal_chat_agent_level1_state_machine_v1_3_model_router.md`  
> 当前代码：branch v3, v1.2 完整状态机  
> 修订原因：审查反馈 — 配置命名空间、调用预算、manual 升级语义、状态枚举、route 传递、provider 档案、gateway retry、ModelAttempt 字段

## 0. 对审查意见的回应

| # | 审查点 | 判定 | 修订 |
|---|---|---|---|
| 1 | 配置命名空间不兼容 | 认同 | `cfg["model"]` 下扩展 `routing`、`flash_profile`、`pro_profile`，不新增 `llm` 顶级 key |
| 2 | max_model_attempts=2 与 FACT_TOOL 冲突 | 认同 | `MAX_TOOL_LOOP=5` 不动；新增 `max_flash_upgrade_attempts=1` 仅限 flash→pro 升级 |
| 3 | manual_flash 是否允许升级未定义 | 认同 | 默认不升级；`manual_flash_allow_upgrade` 显式开关 |
| 4 | 状态枚举不全（缺 MODEL_ERROR_BRANCH） | 认同 | `MODEL_ERROR_BRANCH` 是 `_do_call_llm` 内部私有 if/else，不进入 TurnState |
| 5 | route 未入 TurnScratchpad | 认同 | TurnScratchpad 加 `route` 字段 |
| 6 | ModelProfile 含独立 provider 被高估 | 认同 | profile 只含模型级参数（model_name, temperature, max_tokens, timeout_seconds），provider 共享 |
| 7 | Gateway retry 突破调用预算 | 认同 | `_do_call_llm` 在 flash→pro 场景设 `LLMRequest.retry=0`，由状态机控重试 |
| 8 | ModelAttempt 缺 started_at/finished_at | 认同 | 补全四个时间字段 |

## 1. 配置方案

### 1.1 放在 `cfg["model"]` 下扩展

```yaml
# config.yaml — model 段扩展

model:
  provider: deepseek
  api_key: "${DEEPSEEK_API_KEY}"
  base_url: "${DEEPSEEK_BASE_URL:-}"
  default_model: deepseek-v4-flash

  # ── v1.3: 模型路由 ──────────────────────
  routing_mode: auto                # auto | manual_flash | manual_pro
  max_flash_upgrade_attempts: 1    # flash→pro 最大升级次数（不覆盖 FACT_TOOL 多轮）

  flash_profile:
    model_name: deepseek-v4-flash  # API 模型名
    temperature: 0.8
    max_tokens: 800
    timeout_seconds: 20

  pro_profile:
    model_name: deepseek-v4-pro    # API 模型名
    temperature: 0.7
    max_tokens: 1200
    timeout_seconds: 40

  manual_flash_allow_upgrade: false  # manual_flash 下是否允许升级 pro

  # 以下为 v1.2 现有字段，不动
  native_tool_calls:
    chat_agent: true
    allowed_tools: ["get_time", "get_weather", "send_wechat_messages", "skip_reply"]
  thinking:
    default: disabled
  timeout_s: 60
  max_retries: 1
  temperature: 0.7
```

## 2. 调用预算设计

### 2.1 区分三层预算

| 预算 | 常量/配置 | 限制范围 | 当前值 |
|---|---|---|---|
| 总 LLM 调用 | `MAX_TOOL_LOOP` | 一轮最多调几次模型（含 FACT_TOOL 多轮 + 协议重试 + 升级） | 5 |
| flash→pro 升级 | `max_flash_upgrade_attempts` | flash 失败时最多升级几次 | 1 |
| gateway 内部重试 | `LLMRequest.retry` | 一次 LLM 调用 provider API 内部重试次数 | 0（flash→pro 场景）/ 1（普通场景） |

### 2.2 预算检查逻辑

```python
# _do_call_llm 内部
# 总调用数超限 → HARD_FALLBACK（现有 MAX_TOOL_LOOP 逻辑，不动）

# FLASH_TO_PRO_UPGRADE 内部
# flash_upgrade_count >= max_flash_upgrade_attempts → HARD_FALLBACK
```

**关键**：`MAX_TOOL_LOOP=5` 不变。一个"天气"场景的典型调用序列：
```
CALL_LLM #1 (flash, get_weather)  ← FACT_TOOL
CALL_LLM #2 (flash, 协议违规)     ← 触发升级
CALL_LLM #3 (pro, send_wechat)    ← 终态成功
```
`flash_upgrade_attempts=1` 允许 #2→#3 的升级。`MAX_TOOL_LOOP=5` 给 FACT_TOOL 多轮留够空间。

## 3. manual_flash 升级语义

| routing_mode | flash 协议违规 | flash API 错误 | 行为 |
|---|---|---|---|
| `auto` | 升级 pro（1 次） | 升级 pro | 默认行为 |
| `manual_flash` (allow_upgrade=false) | 不升级 → PROTOCOL_RETRY（同模型）→ 超限 HARD_FALLBACK | 不升级 → HARD_FALLBACK | 严格 flash |
| `manual_flash` (allow_upgrade=true) | 升级 pro（同 auto） | 升级 pro | 手动 + 可升级 |
| `manual_pro` | 不升级 → PROTOCOL_RETRY（同模型）→ 超限 HARD_FALLBACK | 不升级 → HARD_FALLBACK | 严格 pro |

### 4.2 ModelAttempt

```python
@dataclass(slots=True)
class ModelAttempt:
    """v1.3 §9: 一次模型调用尝试记录。"""
    attempt_index: int          # 本轮第几次调用（从 1 开始）
    selected_model: str         # "flash" | "pro"
    routing_mode: str           # "auto" | "manual_flash" | "manual_pro"
    routing_reason: str         # "daily_chat" | "flash_protocol_violation" | ...
    model_name: str             # 实际传给 API 的模型名
    started_at: float = 0.0     # time.time()
    finished_at: float = 0.0    # time.time()
    latency_ms: int = 0         # finished_at - started_at
    result_type: str = ""       # "success" | "llm_error" | "protocol_violation"
    error_type: str = ""        # "timeout" | "empty_response" | "assistant_content_only" | ...
    upgraded_from: str = ""     # "flash"（如果是从 flash 升级来的）
```

定义在 `agent/state_machine.py`。`TurnScratchpad` 新增：

```python
model_attempts: list[ModelAttempt] = field(default_factory=list)
_current_attempt: ModelAttempt | None = field(default=None, repr=False)
_force_model_label: str = ""          # 强制下一次 _select_model() 的模型（"flash"/"pro"），消费后清空
_force_model_upgraded_from: str = ""  # 与 _force_model_label 配对，记录升级来源（如 "flash"），消费后清空
max_flash_upgrade_attempts: int = 1
flash_upgrade_count: int = 0
route: str = ""                       # ChatLite / ChatFull / SystemFastPath
```

## 5. 状态机改动

### 5.1 TurnState 新增

```python
# ── v1.3: model routing ──
FLASH_TO_PRO_UPGRADE = "flash_to_pro_upgrade"   # flash → pro 升级
ROUTE_RETRY_MODEL = "route_retry_model"          # 协议重试 → 选择模型
```

`MODEL_ERROR_BRANCH` **不**进入 `TurnState`。它是 `_do_call_llm` 内部的 if/else：LLM error 发生时，handler 内部判断是 flash（→ `FLASH_TO_PRO_UPGRADE`）还是 pro（→ `HARD_FALLBACK`）。

`MODEL_ROUTER` **不**进入 `TurnState`。它是 `_do_call_llm` 调用前的 `_select_model()` 函数。

### 5.2 新增 state handler

**`_do_flash_to_pro_upgrade`**（`FLASH_TO_PRO_UPGRADE`）：

```python
def _do_flash_to_pro_upgrade(self, turn):
    if turn.flash_upgrade_count >= turn.max_flash_upgrade_attempts:
        turn.add_fallback_event("flash_upgrade_exceeded", ...)
        return TurnState.HARD_FALLBACK
    turn.flash_upgrade_count += 1
    # 强制下一次 _select_model() 选 pro（在所有 routing_mode 分支之前消费）
    turn._force_model_label = "pro"
    # upgraded_from 写到下一次 pro attempt 上，不是当前 flash attempt
    turn._force_model_upgraded_from = "flash"
    logger.info("flash_to_pro_upgrade: count=%d/%d upgrading to pro",
                turn.flash_upgrade_count, turn.max_flash_upgrade_attempts)
    return TurnState.CALL_LLM
```

**`_do_route_retry_model`**（`ROUTE_RETRY_MODEL`）：

```python
def _do_route_retry_model(self, turn):
    """v1.3: inject protocol retry note (same as v1.2 _do_protocol_retry),
    then decide whether to upgrade model or retry same model.

    The retry note is essential — without it, pro would only see the
    original context plus the violating assistant/tool_calls, without
    the corrective instruction '必须调用 send_wechat_messages 或 skip_reply'.
    """
    # ── Step 1: Inject retry note (preserved from v1.2) ──
    turn.protocol_retry_count += 1

    if turn.protocol_retry_count > turn.max_protocol_retries:
        turn.add_fallback_event(
            "protocol_retry_exceeded",
            f"exceeded max protocol retries ({turn.max_protocol_retries})",
        )
        return TurnState.HARD_FALLBACK

    retry_note = "必须调用 send_wechat_messages 或 skip_reply 结束本轮。"
    turn.messages.append({"role": "system", "content": retry_note})
    logger.info(
        "route_retry_model: protocol_retry_count=%d/%d",
        turn.protocol_retry_count, turn.max_protocol_retries,
    )

    # ── Step 2: Decide model for retry ──
    last_attempt = turn.model_attempts[-1] if turn.model_attempts else None
    if last_attempt and last_attempt.selected_model == "flash":
        if self._routing_mode == "manual_flash" and not self._manual_flash_allow_upgrade:
            # manual_flash 不升级 → 同模型重试 → CALL_LLM (flash)
            return TurnState.CALL_LLM
        return TurnState.FLASH_TO_PRO_UPGRADE
    # pro → 同模型重试（不升级 flash）
    return TurnState.CALL_LLM
```

**关键**：`ROUTE_RETRY_MODEL` 注入 retry note 的逻辑与 v1.2 `_do_protocol_retry` 完全一致。协议重试计数和上限检查也保留。区别只在于 Step 2：v1.2 始终回 CALL_LLM，v1.3 先判断是否需要 FLASH_TO_PRO_UPGRADE。`_dispatch()` 中 `PROTOCOL_RETRY` 不再作为独立状态——改为路由到 `ROUTE_RETRY_MODEL`，状态机流转不丢失 retry note 注入。

### 5.3 现有 handler 内部改动

**`_do_call_llm`**：
- 调用前执行 `_select_model(turn)` → 获取 `(label, reason, profile)`
- 创建新 `ModelAttempt`：
  - `attempt_index = len(turn.model_attempts) + 1`
  - `selected_model = label`, `routing_reason = reason`, `model_name = profile.model_name`
  - **消费 `_force_model_upgraded_from`**：如果 `turn._force_model_upgraded_from` 非空 → `attempt.upgraded_from = turn._force_model_upgraded_from` → 清空 `turn._force_model_upgraded_from = ""`
  - `started_at = time.time()`
  - `turn._current_attempt = attempt`
- 设置 `LLMRequest`：
  - `model = profile.model_name`
  - `temperature = profile.temperature`
  - `max_tokens = profile.max_tokens`
  - `timeout_s = profile.timeout_seconds`
  - **如果 `attempt.upgraded_from` 非空**（这是升级后的调用）→ `LLMRequest.retry = 0`（不由 gateway 内部重试，状态机已接管重试控制）
  - 否则 → `LLMRequest.retry = self.config.max_retries`（正常 gateway 重试）
- 调用成功 → `_current_attempt.finished_at = time.time()` → `result_type = "success"`
- 调用失败（LLMError）→ `_current_attempt.finished_at = time.time()` → `result_type = "llm_error"` → 判断 flash/pro → 返回 `FLASH_TO_PRO_UPGRADE` 或 `HARD_FALLBACK`
- 无论成功失败，`turn.model_attempts.append(_current_attempt)`

**`_do_handle_model_output`**：
- protocol violation 时 → `_current_attempt.result_type = "protocol_violation"` + `error_type`
- 返回 `ROUTE_RETRY_MODEL`（替代当前的 `PROTOCOL_RETRY`）

**`_dispatch`**：
- 原 `PROTOCOL_RETRY` 分支改为路由到 `ROUTE_RETRY_MODEL`（`_do_protocol_retry` 的逻辑并入 `_do_route_retry_model`）
- 新增 `FLASH_TO_PRO_UPGRADE`、`ROUTE_RETRY_MODEL` 分支
- `HANDLE_MODEL_OUTPUT` 违规时返回 `ROUTE_RETRY_MODEL`（不再是 `PROTOCOL_RETRY`）
- `CLASSIFY_TOOL_CALLS` 违规时返回 `ROUTE_RETRY_MODEL`（不再是 `PROTOCOL_RETRY`）

### 5.4 `_select_model()` 函数

```python
def _select_model(self, turn: TurnScratchpad) -> tuple[str, str, ModelProfile]:
    """Return (model_label, routing_reason, profile).

    Priority: _force_model_label > manual override > auto rules.
    _force_model_label is set by FLASH_TO_PRO_UPGRADE and consumed here.
    _force_model_upgraded_from is NOT consumed here — it is consumed by
    _do_call_llm when creating the new ModelAttempt.
    """
    # ── 0. 强制选择（FLASH_TO_PRO_UPGRADE 设置，在所有分支之前消费）──
    if turn._force_model_label:
        label = turn._force_model_label
        turn._force_model_label = ""  # 消费一次
        reason = "flash_upgraded_to_pro" if label == "pro" else f"force_{label}"
        profile = self._pro_profile if label == "pro" else self._flash_profile
        return (label, reason, profile)

    # ── 1. 手动模式 ──
    if self._routing_mode == "manual_flash":
        return ("flash", "manual_flash", self._flash_profile)
    if self._routing_mode == "manual_pro":
        return ("pro", "manual_pro", self._pro_profile)

    # ── 2. auto 模式 ──
    # 上一轮 flash 协议违规/错误 → 升级 pro
    last = turn.model_attempts[-1] if turn.model_attempts else None
    if last and last.selected_model == "flash" and last.result_type in (
        "protocol_violation", "llm_error",
    ):
        return ("pro", "flash_failed", self._pro_profile)

    # route-based
    if turn.route == "ChatFull":
        return ("pro", "complex_chat", self._pro_profile)

    # 默认 flash
    return ("flash", "daily_chat", self._flash_profile)
```

## 9. 不做事项

| 事项 | 原因 |
|---|---|
| LLM 自选模型 tool | 系统行为，非聊天动作 |
| 回复质量评分 | 第一版难以定义 |
| 回复后 pro 重写 | 影响发送链路 |
| 用户文本直接切模型 | 安全边界 |
| pro 失败降级 flash | 语义矛盾 |
| GUARD_OUTPUT 拦截后 pro 重写 | 优先保命 |
| 独立 provider 切换 | 同 provider 共享 gateway |
