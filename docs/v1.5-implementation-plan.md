## 0. 现状回顾与目标

### 现状（模式 A — 批量数组发送）

```
模型一次调用 send_wechat_messages(messages=["第一条","第二条","第三条"])
→ 后端 PARSE_VISIBLE_BATCH 解析数组
→ GUARD_OUTPUT 逐条 guard
→ EXEC_SEND_WECHAT 一次调用 wechat_sender(callback) ，内部 for 循环逐条发送
→ DECIDE_SEND_TERMINAL → END_SENT
```

关键事实：
- `send_wechat_messages` = `terminal_tool`，调用即结束 turn
- 工具结果不回灌模型
- 模型不知道自己发了第几条
- `MAX_TOOL_LOOP=5` 只服务于 fact tool 循环

### 目标（模式 B — 严格 CC 因果链）

```
模型调用 wechat_reply(text="第一条")
→ 后端发送一条微信
→ 工具结果 ok 回灌模型
→ 模型调用 wechat_reply(text="第二条")
→ 后端发送第二条
→ 工具结果 ok 回灌模型
→ 模型调用 done(status="replied")
→ 回合结束
```

## 2. Phase 1: 工具层改造（`agent/tool_registry.py`）

### 2.1 新增 `wechat_reply` 工具定义

```python
ToolDef(
    name="wechat_reply",
    description=(
        "发送一条微信消息给用户。每次调用只发送一条微信气泡。"
        "如果想发多条微信，请多次调用此工具，每次传入一条消息。"
        "发送成功后你会收到工具结果，然后可以决定是否继续发下一条。"
        "text 不能包含任何换行符。"
    ),
    args_schema={
        "properties": {
            "text": {
                "type": "string",
                "description": "要发送的一条微信消息内容。不能为空。不能包含任何换行符（\\n）。想发多条请多次调用此工具。",
                "minLength": 1,
                "maxLength": 500,
            },
        },
        "required": ["text"],
    },
    side_effect_level="high",
    native_tool_call_eligible=True,
    tool_category="fact_tool",     # 不新增类别；chat_agent 按 tool_name 分支到专用路径
)
```

v1.5 第一版规则：`wechat_reply.text` **绝对不能出现任何换行符**。出现 `\n` 直接返回 recoverable error，要求模型多次调用 `wechat_reply`。后续版本可考虑允许少量自然换行（段落），但第一版采用最严格策略。

### 2.2 新增 `done` 工具定义

```python
ToolDef(
    name="done",
    description=(
        "显式结束本轮对话。每轮必须以调用 done 结束。"
        "如果你已经发过微信回复，请用 done(status='replied')。"
        "如果你判断不需要回复，请用 done(status='no_reply')。"
        "如果发生无法继续的错误，请用 done(status='failed')。"
    ),
    args_schema={
        "properties": {
            "status": {
                "type": "string",
                "enum": ["replied", "no_reply", "failed"],
                "description": "replied=已回复完成, no_reply=不需要回复, failed=失败结束",
            },
            "note": {
                "type": "string",
                "description": (
                    "简短说明。status=replied 时可省略（可选）；"
                    "status=no_reply 或 failed 时必须填写原因。"
                ),
            },
        },
        "required": ["status"],
    },
    side_effect_level="none",
    native_tool_call_eligible=True,
    tool_category="terminal_tool",
)
```

**done.note 校验规则**（在 `VALIDATE_DONE_ARGS` 中执行）：

| status | note 要求 | 校验失败处理 |
|--------|----------|-------------|
| `replied` | 可选（可空） | 不校验 |
| `no_reply` | **必填**，不能为空 | PROTOCOL_RETRY，提示必须说明原因 |
| `failed` | **必填**，不能为空 | PROTOCOL_RETRY，提示必须说明失败原因 |

### 2.3 移除/隔离旧工具

- `send_wechat_messages`: 从 `allowed_tools` 列表中移除，不再暴露给模型。保留在 `TOOL_REGISTRY` 中用于内部兼容（如旧数据回放），但标记为 `native_tool_call_eligible=False`
- `skip_reply`: 从 `allowed_tools` 列表中移除。保留注册用于内部日志/诊断，标记为 `native_tool_call_eligible=False`

## 3. Phase 2: 工具分类器重写（`agent/tool_classifier.py`）

### 3.1 新分类规则

v1.5 严格单 tool call 模式。分类器只负责：统计数据（0/1/2+ tool calls）、识别工具名、判定合法性。**不引入新 tool_category**。路由由 `chat_agent._dispatch()` 按 `tool_name` 分支。

| 模型输出 | 分类结果 | chat_agent 路由 |
|----------|----------|----------------|
| 0 个 tool call | INVALID | PROTOCOL_RETRY |
| 2+ 个 tool calls | INVALID | PROTOCOL_RETRY |
| 1 个 `get_time` / `get_weather` | known, fact_tool | EXEC_FACT_TOOLS → tool result 回灌 → CALL_LLM |
| 1 个 `wechat_reply` | known, fact_tool（注册类别） | **名称分支** → VALIDATE_REPLY_ARGS → 发送管道 → CALL_LLM |
| 1 个 `done` | known, terminal_tool | VALIDATE_DONE_ARGS → 终态 |
| 1 个未注册/旧工具 | INVALID | PROTOCOL_RETRY |
| 1 个 `send_wechat_messages` / `skip_reply` | deprecated | PROTOCOL_RETRY（带迁移提示） |

### 3.2 `ClassifiedToolCalls` → `ClassifiedSingleToolCall`

重新设计数据结构为单工具场景。**不维护 category 字段用于路由决策**，只用于合法性判断和日志。

```python
@dataclass(slots=True)
class ClassifiedSingleToolCall:
    tool_name: str = ""              # 工具名
    serialized: dict | None = None   # 序列化后的 tool call
    registry_category: str = ""      # TOOL_REGISTRY 中注册的 tool_category（仅参考，不路由）
    is_known: bool = False           # 是否在 TOOL_REGISTRY 中注册
    is_deprecated: bool = False      # 是否为已废弃的旧工具
    deprecated_hint: str = ""        # 废弃工具的迁移提示
    violation_reason: str = ""       # 非法原因（中文）

    @property
    def is_legal(self) -> bool:
        return self.is_known and not self.is_deprecated
```

### 3.3 旧工具检测

检测到 `send_wechat_messages` → `is_deprecated=True, deprecated_hint="send_wechat_messages 已废弃。请使用 wechat_reply 逐条发送，最后用 done 结束。"`
检测到 `skip_reply` → `is_deprecated=True, deprecated_hint="skip_reply 已废弃。请使用 done(status='no_reply', note='原因')。"`

旧工具**绝对不能进入新状态机的任何合法执行路径**。测试必须证明调用旧工具 → PROTOCOL_RETRY，不发送任何微信。

## 5. Phase 4: 状态机主循环重写（`agent/chat_agent.py`）

### 5.1 新状态转移图

```
RECEIVE_EVENT → CREATE_TURN → INTERRUPT_CHECK
  → BUILD_CONTEXT → CLASSIFY_CONTEXT_ERROR
  → OPTIONAL_PREPROCESS
  → CALL_LLM
  → INTERRUPT_CHECK → HANDLE_MODEL_OUTPUT
    ├─ 0 tool calls → PROTOCOL_RETRY
    ├─ 2+ tool calls → PROTOCOL_RETRY
    ├─ old/deprecated tool → PROTOCOL_RETRY (with migration hint)
    └─ 1 tool call → CLASSIFY_ONE_TOOL_CALL
         ├─ get_time / get_weather → EXEC_FACT_TOOLS → tool result 回灌 → CALL_LLM
         ├─ wechat_reply（按名称分支）
         │      ├─ 非法/可修复 → error result 回灌 → CALL_LLM
         │      └─ 合法 → GUARD_OUTPUT
         │           ├─ 致命失败 → HARD_FALLBACK
         │           └─ 通过 → PRE_SEND_INTERRUPT_CHECK
         │                ├─ 被取代 → END_SUPERSEDED_BEFORE_SEND
         │                └─ 仍有效 → EXEC_SEND_ONE
         │                     ├─ 成功 → APPEND_SEND_RESULT
         │                     ├─ 可修复失败 → error result 回灌 → CALL_LLM
         │                     └─ 不可修复 → fatal result 回灌 → CALL_LLM
         │                          → POST_SEND_INTERRUPT_CHECK
         │                               ├─ 用户插话 → END_INTERRUPTED_DURING_REPLY_SEQUENCE
         │                               └─ 无中断 → LIMIT_CHECK
         │                                    ├─ 未超限 → CALL_LLM
         │                                    └─ 超限 → APPEND_SEND_RESULT 中已带 limit_reached=true → CALL_LLM
         │                                         （模型只能 done；若继续 wechat_reply → END_MAX_LIMIT）
         └─ TERMINAL_TOOL (done)
              → VALIDATE_DONE_ARGS
                ├─ 非法 → PROTOCOL_RETRY
                ├─ replied 合法 → END_REPLIED
                ├─ no_reply 合法 → END_NO_REPLY
                └─ failed 合法 → END_FAILED

PROTOCOL_RETRY
  ├─ 未超限 → 注入 retry note → CALL_LLM
  └─ 超限 → HARD_FALLBACK

HARD_FALLBACK
  → GUARD_OUTPUT(硬兜底文案)
    ├─ 通过 → EXEC_FALLBACK_SEND → END_FALLBACK_SENT
    └─ 失败 → END_FAILED
```

### 5.2 关键 handler 实现要点

#### `_do_handle_model_output`

```python
def _do_handle_model_output(self, turn):
    # 中断检查
    if self._is_interrupted():
        return TurnState.END_CANCELLED

    tool_calls = turn._llm_response.tool_calls or []

    # 0 个 tool call → PROTOCOL_RETRY
    if not tool_calls:
        # 检查 assistant.content（可能是旧 JSON / 纯文本）
        ...
        return TurnState.PROTOCOL_RETRY

    # 2+ tool calls → PROTOCOL_RETRY
    if len(tool_calls) > 1:
        turn.add_fallback_event("multiple_tool_calls",
            f"expected exactly 1 tool call, got {len(tool_calls)}")
        return TurnState.PROTOCOL_RETRY

    turn._tool_calls = tool_calls
    return TurnState.CLASSIFY_ONE_TOOL_CALL
```

#### `_do_classify_one_tool_call`

注意：**不依赖 tool_category 做路由**。分类器给出 tool_name + 合法性判断，路由在 chat_agent 中按工具名分支。

```python
def _do_classify_one_tool_call(self, turn):
    tc = turn._tool_calls[0]
    classified = classify_single_tool_call(tc, TOOL_REGISTRY)
    turn._classified_single = classified

    if classified.is_deprecated:
        # 注入废弃提示
        turn.messages.append({"role": "system", "content": classified.deprecated_hint})
        return TurnState.PROTOCOL_RETRY

    if not classified.is_legal:
        return TurnState.PROTOCOL_RETRY

    # ── 按 tool_name 路由，不按 tool_category ──
    name = classified.tool_name
    if name in ("get_time", "get_weather"):
        return TurnState.EXEC_FACT_TOOLS
    elif name == "wechat_reply":
        return TurnState.VALIDATE_REPLY_ARGS
    elif name == "done":
        return TurnState.VALIDATE_DONE_ARGS

    return TurnState.PROTOCOL_RETRY
```

#### `_do_validate_reply_args`

校验 `wechat_reply(text)`：
- `text` 必须是字符串（非数组/非对象）
- `text` 不能为空
- `text` 长度 ≤ 500
- **v1.5 第一版：`text` 绝对不能包含任何换行符（`\n`）**。出现换行即拒绝
- 如果校验失败 → 构造可修复错误 tool result → 回灌 → CALL_LLM

换行拒绝时 tool result：
```json
{"status": "error", "recoverable": true, "reason": "text_contains_newline",
 "hint": "text 不能包含换行符。想发多条请多次调用 wechat_reply。"}
```

#### `_do_exec_send_one`

**关键：发送 guard 后的文本（`turn._guarded_text`），不是原始文本。发送结果必须检查 `wechat_sender` 返回值，不能只靠不抛异常。**

```python
async def _do_exec_send_one(self, turn, wechat_sender):
    guarded_text = turn._guarded_text               # ← guard 后的文本
    original_text = turn._current_reply_text         # 仅用于日志和 VisibleMessage
    tool_call_id = turn._current_tool_call_id
    idempotency_key = f"{turn.turn_id}_{tool_call_id}"

    # ── 幂等检查 ──
    if idempotency_key in turn._sent_idempotency_keys:
        result = {"status": "ok", "delivery": "already_sent",
                  "message_index": turn.sent_message_count}
        turn.messages.append({
            "role": "tool", "tool_call_id": tool_call_id,
            "content": json.dumps(result, ensure_ascii=False),
        })
        return TurnState.APPEND_SEND_RESULT

    # ── 发送单条（使用 guarded_text）──
    send_batch = [{"text": guarded_text, "delay": 0.0, "_vm_index": 0}]
    try:
        raw_results = await wechat_sender(send_batch)
    except Exception as e:
        turn.send_failure_count += 1
        result = {"status": "error", "recoverable": False,
                  "reason": "send_exception", "hint": str(e)[:200]}
        turn.messages.append({
            "role": "tool", "tool_call_id": tool_call_id,
            "content": json.dumps(result, ensure_ascii=False),
        })
        return TurnState.APPEND_SEND_RESULT

    # ── 检查 wechat_sender 返回值的送达状态 ──
    if not raw_results or not isinstance(raw_results, list):
        turn.send_failure_count += 1
        result = {"status": "error", "recoverable": False,
                  "reason": "send_no_result", "hint": "wechat_sender returned empty"}
    else:
        send_status = raw_results[0].get("send_status", "unknown") if raw_results else "unknown"

        if send_status == "delivered":
            turn.sent_message_count += 1
            turn._sent_idempotency_keys.add(idempotency_key)
            vm = VisibleMessage(
                visible_message_id=f"vm_{turn.turn_id}_{turn.sent_message_count}",
                index=turn.sent_message_count,
                original_text=original_text,     # 原始文本（日志用）
                guarded_text=guarded_text,       # 实际发送的文本
                tool_call_id=tool_call_id,
                idempotency_key=idempotency_key,
                delivery_status=DeliveryStatus.SENT_CONFIRMED,
            )
            turn.visible_messages.append(vm)
            result = {"status": "ok", "delivery": "sent",
                      "message_index": turn.sent_message_count}
            # ── 如果达到上限，在本次 tool result 中带 limit_reached=true ──
            if turn.sent_message_count >= turn.max_reply_messages_per_turn:
                result["limit_reached"] = True
                result["hint"] = "本轮微信消息数量已达上限，请调用 done 结束。"
        elif send_status == "failed":
            turn.send_failure_count += 1
            error_detail = raw_results[0].get("send_error", "")
            if "no_bridge" in str(error_detail).lower():
                result = {"status": "error", "recoverable": False,
                          "reason": "wechat_sender_unavailable",
                          "hint": "发送通道不可用，本轮无法继续发送。请调用 done(status='failed')。"}
            else:
                result = {"status": "error", "recoverable": True,
                          "reason": "send_failed",
                          "hint": f"发送失败：{error_detail[:100]}。可以重试或 done。"}
        elif send_status == "blocked":
            result = {"status": "error", "recoverable": True,
                      "reason": "send_blocked",
                      "hint": "消息被拦截（可能为空或包含敏感内容）。请修改后重试。"}
        else:
            turn.send_failure_count += 1
            result = {"status": "error", "recoverable": False,
                      "reason": "send_unknown_status",
                      "hint": f"发送状态未知：{send_status}"}

    # ── 回灌工具结果（不带原文）──
    turn.messages.append({
        "role": "tool",
        "tool_call_id": tool_call_id,
        "content": json.dumps(result, ensure_ascii=False),
    })
    return TurnState.APPEND_SEND_RESULT
```

#### `_do_validate_done_args`

```python
def _do_validate_done_args(self, turn):
    args = parse_done_args(turn._tool_calls[0])

    status = args.get("status", "")
    note = (args.get("note", "") or "").strip()
    sent_count = turn.sent_message_count

    # ── status 合法性 ──
    if status not in ("replied", "no_reply", "failed"):
        return TurnState.PROTOCOL_RETRY

    # ── status 与发送事实一致性 ──
    if status == "replied" and sent_count == 0:
        return TurnState.PROTOCOL_RETRY
    if status == "no_reply" and sent_count > 0:
        return TurnState.PROTOCOL_RETRY

    # ── note 必填校验 ──
    if status in ("no_reply", "failed") and not note:
        # 必须说明原因
        turn.messages.append({
            "role": "system",
            "content": f"done(status='{status}') 时 note 不能为空，请说明原因后重新调用 done。",
        })
        return TurnState.PROTOCOL_RETRY

    turn.done_status = status
    turn.done_note = note

    if status == "replied":
        turn.reply_sequence_status = "completed"
        return TurnState.END_REPLIED
    elif status == "no_reply":
        turn.reply_sequence_status = "no_reply"
        return TurnState.END_NO_REPLY
    else:
        turn.reply_sequence_status = "failed"
        return TurnState.END_FAILED
```

#### `_do_limit_check`

**LIMIT_CHECK 不凭空产生 tool result。上限信息已在 `EXEC_SEND_ONE` 的最后一次 wechat_reply tool result 中通过 `limit_reached=true` 传递给模型。**

```python
def _do_limit_check(self, turn):
    # 检查本轮各项上限
    if turn.sent_message_count >= turn.max_reply_messages_per_turn:
        # 模型此前已收到 limit_reached=true 的 tool result
        # 如果模型此时仍然调用 wechat_reply（而非 done）→ 违规
        turn.reply_sequence_status = "max_limit_reached"
        return TurnState.CALL_LLM
    if turn.send_failure_count >= turn.max_send_failures_per_turn:
        # 发送失败太多次，但仍让模型决定 done(status='failed')
        turn.add_fallback_event("max_send_failures", f"{turn.send_failure_count} failures")
        return TurnState.CALL_LLM
    if turn.llm_call_count >= turn.max_llm_steps_per_turn:
        turn.add_fallback_event("max_llm_steps", f"{turn.llm_call_count} steps")
        return TurnState.HARD_FALLBACK
    return TurnState.CALL_LLM
```

**达到上限后模型继续调 wechat_reply 的处理**（在 `CLASSIFY_ONE_TOOL_CALL` 中）：

```python
# 在 _do_classify_one_tool_call 的 wechat_reply 分支前增加：
if name == "wechat_reply" and turn.sent_message_count >= turn.max_reply_messages_per_turn:
    return TurnState.END_MAX_LIMIT
```

## 15. 风险与注意事项

1. **LLM 步数成本**: 发 10 条消息 = 至少 11 次 LLM 调用（10 次 wechat_reply + 1 次 done），比旧模式（可能只 1 次）显著增加。需要监控 token 消耗和延迟。

2. **tool_choice="required" 的副作用**: 模型每次都必须调工具。如果模型调了 get_time 然后马上 done（不发消息），这可能是合理行为。确保 done 足够灵活。

3. **主动消息接缝**: 主动消息的 scheduler 当前有独立的 7-stage pipeline。并入状态机后，scheduler 只负责"决定是否触发"，实际的上下文构建和发送全部交给 ChatAgent。

4. **wechat_sender 回调签名**: 当前签名是 `async def wechat_sender(messages: list[dict]) -> list[dict]`。单条发送时 messages 列表只有 1 个元素。签名可以保持不变。

5. **回归风险**: 这是核心对话路径的重写。旧路径代码保留在 git 历史中，回退通过 git revert。不保留运行时双状态机。

## 17. 一句话总结

> 把 `send_wechat_messages(messages=[...])` 拆成模型逐条调用 `wechat_reply(text="...")`，每次发一条，收到真实送达结果（检查 wechat_sender 返回值，不只看异常）后再决定下一步，最后用 `done(status, note)` 显式结束。路由按 tool_name 分支（不新增 tool_category），发送用 guarded_text，上限信息嵌入最后一条 wechat_reply 的 tool result。主动消息通过 proactive_meta 标记来源，不伪装成用户消息。旧工具不进入任何合法路径。
