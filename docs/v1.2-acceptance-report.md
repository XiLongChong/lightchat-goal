## 4. 架构变更总结

### 4.1 主链路（Before → After）

**Before (v0.2):**
```
BUILD_CONTEXT → CALL_LLM → HANDLE_MODEL_OUTPUT → CLASSIFY_TOOL_CALLS
→ EXEC_FACT_TOOLS → CALL_LLM (loop)
→ TERMINAL_ACTION_BRANCH → send/skip path → terminal state
(history + hooks handled in main.py)
```

**After (v1.2):**
```
RECEIVE_EVENT → CREATE_TURN → INTERRUPT_CHECK → BUILD_CONTEXT
→ CLASSIFY_CONTEXT_ERROR → OPTIONAL_PREPROCESS → CALL_LLM
→ HANDLE_MODEL_OUTPUT → CLASSIFY_TOOL_CALLS
→ EXEC_FACT_TOOLS → INTERRUPT_CHECK → CLASSIFY_TOOL_ERROR → CALL_LLM (loop)
→ TERMINAL_ACTION_BRANCH → PARSE_VISIBLE_BATCH → GUARD_OUTPUT
→ EXEC_SEND_WECHAT → SEND_RETRY_UNDELIVERED_ONLY → DECIDE_SEND_TERMINAL
→ [terminal state]
→ WRITE_MODEL_HISTORY → POST_TURN_HOOKS → TurnResult
(history + hooks handled inside ChatAgent via injected callbacks)
```

### 4.2 关键边界钉死

| 边界 | 机制 |
|---|---|
| 中断 | 6 处 `INTERRUPT_CHECK`，generation token 机制，production 强制注入 checker |
| 错误分类 | `CLASSIFY_CONTEXT_ERROR` + `CLASSIFY_TOOL_ERROR`，可恢复/致命两级 |
| 输出保护 | 逐条 `guard_single_message`，`VisibleMessage.guard_status` 追踪 |
| 送达追踪 | `DeliveryStatus` 六态模型，`UNKNOWN_AFTER_ATTEMPT` 不重试 |
| 历史隔离 | `WRITE_MODEL_HISTORY` 在 ChatAgent 内，按终态矩阵写入 |
| 后处理 | `POST_TURN_HOOKS` 5 钩子，单失败不阻塞，不改终态 |

### 4.3 删除的旧逻辑

| 旧逻辑 | 处理方式 |
|---|---|
| `wechat_reply` JSON action | 不再解析，检测为 `old_json_actions_detected` → PROTOCOL_RETRY |
| 旧 `skip` action | 不再解析 |
| `assistant.content` 直接发微信 | 进入 PROTOCOL_RETRY |
| `_send_fallback_text` 用模型原文 | 统一使用 `HARD_FALLBACK_TEXT` 系统固定文案 |
| `send_wechat_messages` tool result 回灌模型 | 不回灌 |
| 硬兜底绕过 guard | 也走 `guard_single_message` |
| 多处不统一 fallback 文案 | 统一 `HARD_FALLBACK_TEXT = "我刚刚卡了一下 重新说"` |
| STATE_TOOL 静默 no-op | 严格模式：未注册→PROTOCOL_RETRY |
| main.py 终态历史写入判断 | 移入 ChatAgent post-terminal pipeline |

## 6. 结论

v1.2 改造全部 7 个 Phase 已完成，28 项最低验收标准全部通过。336 个测试用例全部通过，0 个失败。

核心架构已从 v0.2 的 Level-0 状态机升级到 v1.2 的 Level-1 状态机，关键边界（中断、错误分类、输出保护、送达追踪、历史隔离、后处理）全部钉死。

所有未来功能（主动消息、记忆、情绪、搜索、日历）只能作为扩展接入这条主链路，不能另起发送系统。
