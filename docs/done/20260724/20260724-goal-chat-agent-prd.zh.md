## 0. 文档说明

### 0.1 文档目标

本文回答四个问题：

1. Goal Chat Agent 要服务谁；
2. 用户为什么需要这些功能；
3. 产品必须提供什么行为；
4. 什么结果才算功能完成。

本文不规定具体类名、数据库表名、框架调用方式或代码组织方式。开发团队可以重新设计内部结构，但不得省略本文定义的用户能力、业务规则和验收结果。

### 0.2 需求优先级

| 等级 | 含义 |
|---|---|
| P0 | 首个可正式使用版本必须完成；缺少时产品不能替代日常使用 |
| P1 | 稳定版应完成；允许在首个版本后补充 |
| P2 | 已确认的后续方向；不影响首个版本发布 |

### 0.3 规范词

- “必须”“不得”：硬性验收条件；
- “应该”：默认产品行为，若不采用需要记录原因；
- “可以”：可选行为，不作为验收阻塞项；
- “用户可见消息”：最终显示在聊天界面中的一条消息；
- “会话”：一个用户与一个目标 Agent 之间持续存在的对话空间；
- “轮次”：一次用户输入或一次系统触发，以及由此产生的全部动作和回复；
- “渠道”：微信、AsPocket App、HTTP 等消息入口或出口；
- “管理员”：维护本地服务、配置渠道与查看运行状态的人。

## 1. 产品概述

### 1.1 产品定位

Goal Chat Agent 是一个面向个人长期使用的聊天型智能 Agent。它通过自然聊天与用户保持连续交流，并能够在用户需要时查询时间、天气和网络资料，维护经用户确认的长期记忆，管理待办和提醒，以及在用户允许的范围内主动联系用户。

产品的重点不是回答一次问题，而是让用户在多次、跨天、跨设备入口的交流中，仍然面对同一个可理解其上下文的 Agent。

### 1.2 产品要解决的核心问题

| 用户问题 | 产品解决方式 |
|---|---|
| 每次聊天都要重新解释背景 | 保留近期对话、每日摘要和长期记忆 |
| Agent 只会说“我帮你做了”，却没有真正执行 | 通过受控能力完成查询、待办和提醒动作 |
| 回复像客服或模板，缺少稳定风格 | 使用可替换的人格 Markdown 文件约束表达方式 |
| 提醒可能丢失、重复或时间错误 | 保存提醒状态，明确时区，并记录投递结果 |
| 主动消息容易打扰 | 提供安静时段、频率档位、每日上限和关闭开关 |
| 微信、App 和接口行为不一致 | 定义统一身份、消息、附件和轮次规则 |
| 服务出问题时不知道哪里坏了 | 管理后台展示渠道、模型、能力和调度状态 |
| 手机上的其他 Agent 难以接入 | 提供外部 Agent 注册、接收消息和回传回复能力 |

### 1.3 产品原则

1. **连续性优先**：用户不应因为重启或更换入口而丢失必要上下文。
2. **真实动作优先**：涉及查询或写入时，结果必须来自真实能力执行。
3. **用户控制优先**：记忆、提醒、主动联系和敏感信息必须可查看、可关闭或可删除。
4. **消息真实性优先**：界面中每条发送成功的消息都对应一次明确的投递结果。
5. **失败可理解**：产品不得把依赖未配置、网络失败或权限不足伪装成成功。
6. **能力而非工具名**：产品验收关注用户能完成什么，不要求保留内部工具数量和命名。
7. **单用户可用、身份可隔离**：首要场景是个人部署，但所有会话和数据必须有明确身份边界。

### 1.4 产品边界

首个版本不包括：

- 面向公众开放注册的 SaaS；
- 组织、企业和复杂角色权限体系；
- 计费、套餐和商业订阅；
- 任意代码执行、终端操作或自动修改项目文件；
- 通用插件市场；
- 自动启动或管理第三方 Agent 进程；
- 语音通话、音频消息和视频消息；
- 任意文件类型传输；
- 未经用户明确授权的高敏手机数据采集；
- 为展示复杂度而拆分出的多角色 Agent。

## 2. 用户与使用场景

### 2.1 角色定义

#### U1：聊天用户

聊天用户通过微信或 AsPocket 与 Agent 沟通。其主要诉求是：

- 回复自然且风格稳定；
- Agent 能接续近期对话；
- Agent 能记住明确要求记住的稳定信息；
- 提醒准确且不会重复；
- 能查询实时信息并说明来源；
- 不被不合时宜的主动消息打扰；
- 可以知道 Agent 到底做了什么。

聊天用户不需要理解模型调用、上下文窗口、工具调用或调度器等技术概念。

#### U2：本地管理员

本地管理员通常也是聊天用户本人，负责：

- 完成首次配置；
- 选择或替换人格文件；
- 连接微信、App 和第三方服务；
- 查看模型、渠道和能力是否可用；
- 管理记忆、提醒、附件和会话；
- 执行手动发送、摘要和数据清理；
- 在故障时获得明确诊断信息。

#### U3：AsPocket 客户端

AsPocket 通过接口完成：

- 获取内置 Agent 资料；
- 展示可用联系人；
- 发送文字、图片或贴纸；
- 查询消息历史；
- 重试消息而不重复创建；
- 上传低敏 Phone Context；
- 与外部 Agent 联系人进行消息交互。

#### U4：外部 Agent

外部 Agent 是独立运行的进程。它可以：

- 注册为 AsPocket 中的一个联系人；
- 定期报告在线状态；
- 接收发给自己的消息；
- 返回一条或多条回复；
- 主动下线。

外部 Agent 自己负责启动、停止、工作目录和模型配置。

### 2.2 主要使用场景

#### 场景 A：首次使用

1. 管理员启动服务；
2. 后台显示必须配置的项目；
3. 管理员选择人格 Markdown 文件；
4. 管理员配置模型和所需第三方能力；
5. 管理员完成微信扫码或 App 接入；
6. 用户发送第一条消息；
7. 后台确认接收和发送均可用。

成功结果：用户可以开始聊天；缺失的非必需能力会显示为不可用，但不阻止基础聊天。

#### 场景 B：持续聊天

1. 用户连续发送一条或多条消息；
2. 系统把同一时间段内的消息视为一次完整输入；
3. Agent 读取适量近期上下文；
4. Agent 根据需要查询能力；
5. Agent 发送一条或多条自然消息；
6. 系统记录本轮已发送内容和完成状态。

成功结果：用户看到的消息顺序正确，不出现内部指令、调用参数或重复回复。

#### 场景 C：创建提醒

1. 用户说出事项和时间；
2. 时间有歧义时 Agent 询问；
3. 时间明确后创建提醒；
4. Agent 告知具体触发时间；
5. 到期后向用户发送预定消息；
6. 用户可以查询或取消未触发提醒。

成功结果：提醒在正确时区触发；重启不会导致提醒消失或重复。

#### 场景 D：跨天接续

1. 用户当天进行了较长交流；
2. 系统在合适的时间形成当日摘要；
3. 次日用户继续聊天；
4. Agent 能利用摘要理解必要背景；
5. 临时闲聊不会被错误地保存为长期事实。

成功结果：Agent 保留关键上下文，同时避免把全部历史无限加入每次请求。

#### 场景 E：App 联系外部 Agent

1. 外部 Agent 注册并保持在线；
2. AsPocket 获得联系人信息；
3. 用户选择联系人并发送消息；
4. 消息到达对应外部 Agent；
5. 外部 Agent 返回一条或多条回复；
6. AsPocket 按顺序展示本轮内容。

成功结果：消息不会串到其他联系人；重试不会产生重复用户消息。

## 3. 成功标准

### 3.1 产品目标

- P0 功能验收通过率为 100%；
- 用户消息重复提交不会产生重复记录或重复回复；
- 已确认发送成功的消息不会因重试再次发送；
- 服务重启后，会话、提醒和必要的待投递消息可以恢复；
- 用户可以查看和管理长期记忆；
- 管理员可以识别模型、微信、天气、联网搜索和 To Do 的可用状态；
- 人格文件可以直接替换，不需要修改业务代码；
- 微信、App、HTTP 和外部 Agent 的身份与消息边界清晰；
- 高敏信息不会出现在日志、普通接口响应或 Agent 回复中。

### 3.2 质量指标

| 指标 | P0 目标 |
|---|---|
| 基础聊天可用率 | 在模型与渠道正常时 ≥ 99% |
| 同一消息重复提交产生的重复消息数 | 0 |
| 提醒重启恢复率 | 100% |
| 已确认投递的重复发送数 | 0 |
| 跨联系人消息串线数 | 0 |
| 高敏字段日志泄露数 | 0 |
| P0 接口契约测试通过率 | 100% |
| 管理后台关键状态可诊断率 | 100% |
| 固定日期导致的时间类测试失败数 | 0 |

### 3.3 回复验收边界

模型生成内容具有非确定性，因此不要求同一个问题每次逐字一致。验收关注：

- 是否符合选定人格；
- 是否理解必要上下文；
- 是否使用正确能力；
- 是否真实完成动作；
- 是否遵守消息条数、隐私和安全规则；
- 是否在失败时给出准确说明。

## 4. 产品通用规则

### PRD-G-001：统一身份

- 每个业务数据都必须归属于明确用户；
- 渠道帐号是用户的登录或通信标识，不直接等于产品用户身份；
- 同一用户可以绑定多个渠道；
- 不同用户的数据不得共享；
- AsPocket 中不同 `remoteAgentId` 的消息历史必须隔离；
- 管理员手动操作必须明确作用于哪个用户或会话。

验收：

- 两个用户发送相同内容时，历史、记忆、提醒互不可见；
- AsPocket 切换联系人后，不显示另一个联系人的消息；
- 无法识别用户身份时，系统拒绝写入业务数据。

### PRD-G-002：统一轮次

每次轮次必须具备：

- 唯一轮次编号；
- 触发来源；
- 用户和会话；
- 输入消息；
- 开始时间与结束时间；
- 用户可见回复；
- 使用过的能力；
- 完成或失败状态。

轮次来源至少包括：

- 用户普通消息；
- 定时提醒；
- 主动对话检查；
- 管理员手动触发；
- 外部 Agent 回调。

### PRD-G-003：同会话顺序

- 同一会话的用户消息按到达顺序处理；
- 不同会话可以并行；
- 新消息到达时，系统可以结束尚未发送的上一轮；
- 上一轮已经成功发送的内容不得撤回、修改或再次发送；
- 被中断的轮次必须有明确状态；
- 后续上下文只能包含真实发生过的用户输入和用户可见回复。

### PRD-G-004：幂等

以下动作必须支持幂等：

- App 发送消息；
- 外部 Agent 回传回复；
- 待投递消息确认；
- 提醒触发；
- 渠道投递；
- 第三方待办写入。

重复请求必须返回同一业务结果，或者明确说明此前结果，不得产生第二份业务副作用。

### PRD-G-005：失败状态

产品至少区分：

- 请求尚未执行即失败；
- 已确认执行失败；
- 已确认执行成功；
- 请求超时但结果未知；
- 已完成部分回复后失败；
- 因新消息到达而终止；
- 因达到安全上限而终止。

“超时”不得直接描述为“没有执行”。结果未知时应提示用户核对，禁止自动重复高副作用动作。

### PRD-G-006：时间与时区

- 所有面向用户的时间必须包含或继承明确时区；
- 默认时区可配置，默认值为 `Asia/Shanghai`；
- 接口时间使用带时区的 ISO 8601 格式；
- 相对时间必须以当前权威时间计算；
- 过去时间不能创建为未来提醒；
- 夏令时、跨日和跨年场景必须有测试；
- 管理后台同时显示本地时间和必要的状态说明。

### PRD-G-007：配置生效与反馈

- 配置保存前必须校验格式和范围；
- 保存成功后明确说明是否立即生效、下轮生效或需要重启；
- 密钥只显示“已配置/未配置”，不得回显原文；
- 依赖缺失只影响相关能力，不应使无关基础聊天不可用；
- 配置冲突时必须给出具体字段和解决方法。

## 5. 对话与人格

### 5.1 基础对话

#### PRD-CONV-001：文字输入

- 支持单条文字消息；
- 支持短时间内多条连续消息合并为一次输入；
- 合并后保留原始顺序；
- 空文本、仅空白文本和超过限制的文本应被拒绝；
- 用户输入不得被当作系统指令直接执行；
- 渠道不支持的内容类型应返回可理解提示。

#### PRD-CONV-002：多消息回复

- Agent 可以在一轮内发送一条或多条消息；
- 每次发送动作对应一个用户可见气泡；
- 多条消息按照发送顺序展示；
- 不能把一条消息在程序中任意切碎来伪装多气泡；
- 查询结果、内部思考和能力返回值不会自动成为气泡；
- 没有成功发送的文本不得写入用户可见历史。

#### PRD-CONV-003：回复完成

一轮对话在以下任一情况结束：

- 已发送回复且 Agent 不再执行动作；
- Agent 明确决定无需回复；
- 发生不可恢复错误；
- 用户新消息使本轮失效；
- 达到轮次、能力调用或消息数量上限。

结束时必须记录：

- 是否发送消息；
- 发送了几条；
- 是否执行能力；
- 最终状态；
- 可供管理员理解的失败原因。

#### PRD-CONV-004：自然交流

- 回复语言默认跟随用户；
- 中文场景使用自然中文；
- 不向用户展示内部工具名、调用编号、JSON 或系统提示；
- 不以“作为 AI”等固定免责声明破坏人格，法律或安全场景除外；
- 不伪装已完成未执行的动作；
- 不确定时表达不确定，并在可行时查询信息或向用户确认。

### 5.2 上下文

#### PRD-CONV-005：上下文组成

Agent 可使用的上下文包括：

1. 产品安全与行为规则；
2. 当前选定的人格文件；
3. 当前日期、时间和时区；
4. 本轮用户输入；
5. 近期真实对话；
6. 已形成的会话摘要；
7. 与本轮相关的长期记忆；
8. 本轮能力执行结果；
9. 可选的低敏 Phone Context。

不得加入：

- 其他用户的历史；
- 其他 AsPocket 联系人的历史；
- 未发送成功的草稿；
- 管理后台密码或第三方密钥；
- 与本轮无关的大量原始日志；
- 已删除或已明确失效的记忆。

#### PRD-CONV-006：上下文容量

- 系统必须在超过模型容量前主动控制上下文；
- 优先保留当前输入、最近对话、相关记忆和必要摘要；
- 截断或摘要不能改变谁说了什么；
- 管理后台应展示最近一轮上下文使用情况；
- 容量不足时应结束本轮并给出可诊断错误，不得发送残缺内部内容。

#### PRD-CONV-007：空闲时间

Agent 应能知道距离该用户上次发言的大致时长，以便区分连续聊天和久别后的新话题。此信息只用于改善交流，不应被保存为长期个人事实。

### 5.3 人格文件

#### PRD-CONV-008：人格是可替换配置

- 人格以 UTF-8 Markdown 文件提供；
- 人格文件不是写死在产品中的角色；
- 不同部署可以使用不同人格文件；
- 同一个人格文件可以直接复制到其他项目复用；
- 新项目只需提供示例模板和文件加载入口，不要求携带某个具体人格内容；
- 人格文件不属于必须导入的业务数据；
- 本文不限制人格文件的授权方式或使用范围；
- 人格文件只定义交流风格、称呼、边界和偏好，不得覆盖产品安全规则。

#### PRD-CONV-009：人格选择与替换

管理员必须能够：

- 查看当前使用的文件；
- 查看内容预览；
- 选择另一个合法 Markdown 文件；
- 保存修改；
- 知道修改从哪一轮开始生效；
- 在文件不可读或格式无效时继续使用最近一次有效版本；
- 获得明确错误而不是空人格运行。

验收：

- 替换文件后，新轮次使用新人格；
- 已有对话记录不被改写；
- 文件删除或读取失败时，基础服务不崩溃；
- 人格内容无法要求系统泄露密钥、越权读写或绕过工具权限。

#### PRD-CONV-010：人格内容质量

人格模板应该允许描述：

- 身份与称呼；
- 语气与表达习惯；
- 回复长短偏好；
- 情绪回应方式；
- 主动联系风格；
- 明确禁止的表达；
- 与用户关系的边界。

产品不应把业务接口、数据库规则或密钥写入人格文件。

### 5.4 输出保护

#### PRD-CONV-011：发送前检查

发送前必须阻止或处理：

- 系统提示和内部协议；
- 工具调用参数和调用编号；
- API 密钥、令牌和密码；
- 不完整的结构化数据；
- 超出渠道长度限制的消息；
- 明确重复的同轮消息；
- 不受支持的控制字符。

#### PRD-CONV-012：保护结果可诊断

管理员能够看到：

- 哪一轮触发保护；
- 触发的规则类别；
- 动作是阻止、替换还是截断；
- 是否影响了投递。

诊断信息不得包含被保护的秘密原文。

## 6. Agent 能力

### 6.1 能力梳理结论

模型可调用项在产品层归并为七类能力：

1. 发送自然语言消息；
2. 查询当前时间；
3. 查询天气；
4. 搜索网络并阅读指定网页；
5. 查看、创建和更新长期记忆；
6. 查看与管理 Microsoft To Do；
7. 创建、查询和取消提醒。

“安排下一次主动联系”归属于主动对话策略，只能在主动检查场景中使用，不作为普通聊天能力。

内部可以按需要拆分或合并调用项。产品验收不要求固定为 14 个名称，也不要求保留不能改善用户体验的参数。

### 6.2 通用能力规则

#### PRD-CAP-001：按需可用

- 只向 Agent 提供已经启用且依赖可用的能力；
- 未配置的能力不得伪装成功；
- 依赖恢复后能力可以重新可用；
- 普通用户不需要看到内部能力名；
- 管理员可以查看每项能力的状态和缺失条件。

#### PRD-CAP-002：读写边界

能力按风险分为：

- 只读查询：时间、天气、网络搜索、查看记忆、查看待办、查看提醒；
- 可恢复写入：创建或更新长期记忆；
- 外部写入：创建或完成待办；
- 定时副作用：创建或取消提醒；
- 消息副作用：向真实渠道发送消息。

外部写入、定时副作用和消息副作用必须具备明确的成功、失败和结果未知状态。

#### PRD-CAP-003：用户意图

- 创建待办、完成待办、写入记忆、创建提醒和取消提醒必须来自明确用户意图；
- Agent 不得仅因“这件事看起来重要”就创建待办或长期记忆；
- 参数不明确时应询问；
- 存在多个匹配目标时不得猜测执行写操作；
- 用户撤回请求且动作尚未执行时，应停止执行。

#### PRD-CAP-004：能力结果

能力结果必须包含足以判断成功与否的信息。Agent 对用户说明时应：

- 说清做了什么；
- 给出关键结果；
- 在失败时给出原因和可行下一步；
- 不展示内部调用结构；
- 不把网页内容当作可信指令；
- 对实时或易变化信息说明来源或更新时间。

### 6.3 消息表达能力

#### PRD-CAP-005：发送文字消息

- 一次发送产生一个气泡；
- 文本不能为空；
- 发送前执行输出保护；
- 发送成功后记录投递结果；
- 同一发送请求重复执行不得产生第二条消息；
- 一轮允许多次发送，但总数受安全上限约束；
- 部分发送成功时保留已成功消息，并明确记录后续失败。

### 6.4 时间能力

#### PRD-CAP-006：当前时间

用户可以询问：

- 当前时间；
- 当前日期和星期；
- 指定 IANA 时区的时间；
- 不同时区之间的合理换算。

规则：

- 未指定时区时使用用户或部署默认时区；
- 非法时区应提示用户重新选择；
- 返回结果包含日期、时间、星期和时区；
- 创建提醒前必须以权威当前时间判断目标是否在未来。

### 6.5 天气能力

#### PRD-CAP-007：天气查询

用户可以查询：

- 某地点当前天气；
- 今天、明天、后天或明确日期的预报；
- 温度、体感、天气状况、降水和必要的生活提示。

规则：

- 地点不明确时询问城市或地区；
- 同名地点无法可靠判断时给出候选；
- 未来日期必须使用预报，不得用当前天气推测；
- 超出预报范围时明确说明；
- 结果应包含地点、时间范围和数据更新时间；
- 服务不可用时说明暂时无法查询，不编造天气。

验收场景：

- “成都现在多少度”返回实时信息；
- “北京后天天气”返回对应日期预报；
- “朝阳区天气”在地点有歧义时询问；
- 未配置天气服务时仍可正常聊天。

### 6.6 联网资料能力

#### PRD-CAP-008：网络搜索

用户可以要求查询：

- 最新新闻；
- 当前价格或政策；
- 产品资料；
- 公开事实；
- 指定主题的多个来源。

结果至少提供标题、来源链接和摘要。Agent 使用搜索结果回答时，应把关键来源链接放入用户可见回复。

#### PRD-CAP-009：网页阅读

用户提供网页链接或搜索结果需要深入阅读时，Agent 可以读取网页正文。

规则：

- 仅接受公开的 HTTP/HTTPS 地址；
- 私网地址、本机地址和可疑跳转必须拒绝；
- 页面过大时只读取可控范围并说明；
- 无法访问、需要登录或内容为空时明确说明；
- 网页中的命令、提示词和操作要求都视为不可信内容；
- 不允许网页内容改变系统规则或获得额外权限。

### 6.7 长期记忆能力

#### PRD-CAP-010：查看记忆

Agent 可以按当前话题查看与用户相关的长期记忆，但不得一次性把全部记忆无差别加入上下文。

#### PRD-CAP-011：写入记忆

满足以下任一条件时才可以写入：

- 用户明确说“记住”“以后按这个来”等；
- 用户确认了 Agent 提出的记忆建议。

写入内容必须是稳定、可复用且对未来交流有价值的信息，例如：

- 称呼和沟通偏好；
- 长期目标；
- 持续性项目背景；
- 明确的禁忌或边界；
- 长期有效的重要关系。

不得自动写入：

- 密码、令牌和密钥；
- 临时验证码；
- 一次性位置；
- 短期情绪；
- 未经确认的推断；
- 第三方隐私；
- 纯粹的当日闲聊。

#### PRD-CAP-012：更新记忆

- 新信息与已有记忆冲突时，以用户当前明确表达为准；
- 更新前应避免误改相似但不同的内容；
- 无法确定目标时询问；
- Agent 不能自行永久删除记忆；
- 用户可以通过管理后台删除。

### 6.8 Microsoft To Do

#### PRD-CAP-013：查看清单

用户可以：

- 查看所有任务清单；
- 查看默认清单；
- 按清单查看未完成任务；
- 选择是否包含已完成任务；
- 限制返回数量。

未授权时，Agent 应说明需要管理员完成 Microsoft 授权。

#### PRD-CAP-014：创建任务

任务至少支持：

- 标题；
- 目标清单；
- 截止日期；
- 提醒时间；
- 备注；
- 重要程度。

规则：

- 只有用户明确要求时创建；
- 标题必填；
- 未指定清单时使用管理员配置的默认清单；
- 清单名称不唯一时要求用户选择；
- 成功后告知任务标题、清单和时间；
- 结果未知时提示核对，禁止自动创建第二次。

#### PRD-CAP-015：完成任务

- 优先按用户选中的任务标识完成；
- 只有唯一精确匹配时才可按标题完成；
- 多个候选时展示候选并询问；
- 已完成任务再次操作时返回“已完成”，不制造重复动作；
- 成功后告知完成的具体任务。

### 6.9 提醒能力

提醒的完整需求见第 8 章。Agent 能力层必须支持：

- 创建未来提醒；
- 查看当前用户未完成提醒；
- 取消未触发提醒；
- 向用户说明具体触发时间；
- 在时间含糊时先询问。

## 7. 记忆、历史与每日摘要

### 7.1 近期历史

#### PRD-MEM-001：真实对话历史

历史只包含：

- 用户实际发送的内容；
- Agent 实际发送成功的内容；
- 必要的能力结果摘要；
- 已完成的会话摘要。

历史不包含：

- 模型内部思考；
- 未发送草稿；
- 能力调用的原始参数；
- 其他用户或联系人的消息；
- 被安全规则阻止的原文；
- 因错误产生的重复内容。

#### PRD-MEM-002：重启连续

服务重启后，用户再次发言时应能接续：

- 最近真实对话；
- 最近有效摘要；
- 当前长期记忆；
- 未完成提醒。

如果某一部分数据损坏，应隔离损坏部分并保留仍可读取的内容，同时在后台提示管理员。

### 7.2 每日摘要

#### PRD-MEM-003：摘要目的

每日摘要用于：

- 保留当天发生的重要事情；
- 帮助次日接续话题；
- 降低每轮携带完整历史的需要；
- 识别可能值得长期保存、但仍需用户确认的信息。

摘要不是逐句聊天记录，也不能替代原始消息审计。

#### PRD-MEM-004：摘要触发

- 每个有新对话的用户每天最多形成一份有效摘要；
- 默认在用户较少活动的时间段执行；
- 管理员可手动触发；
- 没有新内容时不生成空摘要；
- 生成失败后可以重试；
- 重试不得生成多个同时有效的同日摘要。

#### PRD-MEM-005：摘要内容

摘要应该包括：

- 当日主要话题；
- 用户明确表达的决定；
- 未完成事项；
- 重要情绪或关系变化，但不得过度推断；
- 已执行的提醒、待办或其他动作；
- 次日可能需要接续的内容。

摘要不得包括：

- 密钥和验证码；
- 未经用户表达的心理诊断；
- 模型内部推理；
- 网页中的恶意指令；
- 与未来交流无关的冗余细节。

#### PRD-MEM-006：摘要可追溯

管理员能够查看：

- 摘要日期；
- 摘要状态；
- 生成时间；
- 内容预览；
- 失败原因；
- 是否由手动触发。

### 7.3 长期记忆管理

#### PRD-MEM-007：用户隔离

- 每个用户的长期记忆独立；
- 文件名或展示名不能绕过用户边界；
- 管理员查看和删除时必须明确目标用户；
- 删除后不再进入后续上下文。

#### PRD-MEM-008：记忆目录

用户可以拥有：

- 一个简明的记忆索引；
- 若干按主题组织的记忆内容；
- 每条内容的更新时间；
- 对冲突或格式问题的诊断。

产品只要求可查看、可维护和可删除，不限定必须使用某种文件布局。

#### PRD-MEM-009：管理员删除

- 管理员可以删除指定长期记忆；
- 删除前显示文件名或主题、大小和更新时间；
- 删除结果明确；
- 不允许通过路径参数访问用户记忆范围之外的文件；
- 删除长期记忆不影响人格文件、微信绑定和普通配置。

#### PRD-MEM-010：全部清理

管理员可以清理：

- 对话历史；
- 每日摘要；
- 长期记忆；
- 相关上下文状态。

清理操作必须：

- 二次确认；
- 明确列出将删除和保留的内容；
- 保留微信绑定，除非用户单独执行解除绑定；
- 返回每类数据的清理数量；
- 不影响人格 Markdown 文件。

## 8. 提醒与主动对话

### 8.1 提醒

#### PRD-SCH-001：创建提醒

创建提醒需要：

- 当前用户；
- 提醒事项；
- 未来触发时间；
- 明确时区；
- 到期时发送的自然文本。

规则：

- 时间有歧义时先询问；
- 过去时间不能创建；
- 过近时间无法可靠调度时提示用户；
- 过远时间超出产品限制时提示限制；
- 到期文本不得包含内部格式；
- 创建成功后返回提醒编号和用户本地时间；
- 相同请求重试不创建第二条。

#### PRD-SCH-002：查询提醒

用户可以查看自己的未完成提醒。每条至少展示：

- 提醒事项；
- 触发时间；
- 时区；
- 当前状态；
- 可用于取消的标识。

默认不显示其他用户和已清理历史。

#### PRD-SCH-003：取消提醒

- 只有未触发的提醒可以取消；
- 已取消提醒再次取消时返回“已取消”；
- 已发送提醒不能描述为取消成功；
- 正在投递且结果未知时，返回真实状态并避免二次发送；
- 取消结果必须持久保存。

#### PRD-SCH-004：到期投递

到期后：

1. 检查提醒仍然有效；
2. 选择可用且允许主动发送的渠道；
3. 发送预定文本；
4. 保存投递结果；
5. 标记最终状态。

最终状态至少包括：

- 待触发；
- 已取消；
- 投递中；
- 已发送；
- 已确认失败；
- 结果未知；
- 已过期未发送。

#### PRD-SCH-005：重启恢复

- 服务重启后自动恢复未完成提醒；
- 到期但尚未处理的提醒按补发策略处理；
- 恢复时不得同时产生多个执行实例；
- 已发送提醒不会再次发送；
- 管理后台显示恢复后的真实状态。

### 8.2 主动对话

#### PRD-SCH-006：开关与频率

管理员可以：

- 全局开启或关闭主动对话；
- 选择低、中、高频率档位；
- 查看每个档位对应的每日上限；
- 查看当天已使用次数；
- 配置安静时段和时区。

后台展示的规则必须与实际生效规则一致。

#### PRD-SCH-007：主动联系资格

只有同时满足以下条件时才可以主动联系：

- 功能已开启；
- 存在可以主动发送的联系人；
- 当前不在安静时段；
- 未达到每日上限；
- 距离上次主动消息已超过冷却时间；
- 近期没有未回复的主动消息；
- 没有活跃的普通用户轮次；
- 当前渠道可用。

#### PRD-SCH-008：主动内容

- 主动消息应符合人格；
- 内容应与近期对话或合理关心有关；
- 不应仅为消耗配额而发送空洞问候；
- 不应反复追问用户未回复的话题；
- 不得泄露长期记忆中的敏感细节；
- 用户明确表示不想被主动联系时，应关闭或降低频率。

#### PRD-SCH-009：下一次检查

主动检查可以提出下一次检查的建议时间，但最终时间必须重新经过：

- 安静时段；
- 每日上限；
- 最小和最大间隔；
- 渠道可用性；
- 用户开关。

普通聊天中不得让 Agent 自行安排无限主动任务。

## 9. 微信渠道

### PRD-WX-001：扫码连接

管理员可以在后台：

- 发起微信连接；
- 查看二维码；
- 查看等待、已扫描、已确认、已过期和失败状态；
- 连接成功后看到脱敏凭据状态；
- 启动或停止微信消息桥接；
- 在二维码过期后重新发起。

### PRD-WX-002：联系人建立

- 第一次收到用户真实消息后建立可发送联系人；
- 联系人记录包括用户标识、会话凭据、Bot 标识和更新时间；
- 只有属于当前 Bot 的有效联系人才能用于主动发送；
- 普通对话清理、摘要或记忆删除不得删除联系人绑定；
- 解除绑定是独立高风险操作，必须二次确认。

### PRD-WX-003：接收消息

- 支持文字消息；
- 支持将短时间内同一用户的连续消息按顺序合并；
- 每条入站消息都有唯一标识和顺序；
- 重复拉取不会重复创建用户输入；
- 不支持的消息类型记录为可诊断事件，并按产品规则提示或忽略；
- 微信暂时断开时自动恢复接收。

### PRD-WX-004：发送消息

- 发送前确认联系人和渠道仍有效；
- 每个用户可见气泡对应一次发送；
- 发送结果必须区分成功、失败和未知；
- 同一发送重复请求不产生第二条微信消息；
- 多条消息按顺序发送；
- 某一条失败后，后续是否继续必须有统一规则并留下结果。

### PRD-WX-005：渠道状态

后台至少展示：

- 是否已配置；
- 是否正在运行；
- 是否收到过用户消息；
- 是否可以主动发送；
- 最近一次错误；
- 当前连接模式；
- 最近一次成功收发时间。

## 10. AsPocket App

### 10.1 通用规则

#### PRD-APP-001：鉴权优先

- 所有业务接口先鉴权，再解析可能较大的正文或附件；
- 未授权请求不得创建消息、附件或 Phone Context；
- 错误响应不得泄露有效凭据或内部路径。

#### PRD-APP-002：联系人隔离

- 内置 Agent 使用稳定联系人标识；
- 每个外部 Agent 使用独立 `remoteAgentId`；
- 消息、附件引用和幂等键都必须包含联系人边界；
- 同一 `clientMessageId` 可以在不同联系人下存在；
- 联系人离线不影响查看已有历史。

### 10.2 Profile 与联系人

#### PRD-APP-003：内置 Agent 资料

App 可以获取：

- 稳定联系人 ID；
- 展示名称；
- 头像或头像标识；
- 简介；
- 在线或可用状态；
- 支持的消息类型。

展示内容可以由配置提供，不要求从人格文件全文推导。

#### PRD-APP-004：联系人邀请

App 可以获取当前可添加的联系人，包括：

- 内置 Agent；
- 已注册且允许展示的外部 Agent；
- 联系人 ID；
- 展示名称；
- 简介；
- 在线状态；
- 会话类型；
- 支持能力。

同一联系人不得重复出现在邀请列表。

### 10.3 消息

#### PRD-APP-005：发送文字

请求至少包含：

- `clientMessageId`；
- `remoteAgentId`；
- 文字内容；
- 可选附件；
- 客户端创建时间。

成功响应至少包含：

- 标准化后的用户消息；
- 本轮产生的 Agent 回复数组；
- 轮次编号；
- 路由类型；
- 是否命中幂等结果。

#### PRD-APP-006：回复数组

- 每次成功的 Agent 发送对应 `agentReplies[]` 中一项；
- 回复保持真实顺序；
- 内部思考和能力结果不出现在数组中；
- 没有回复时返回空数组；
- 部分回复成功时返回已成功部分和轮次状态；
- 首次请求与重复请求返回同一种结构。

#### PRD-APP-007：消息历史

App 可以按联系人分页查询历史。每条消息至少包含：

- 远端消息编号；
- 可选客户端消息编号；
- 角色；
- 内容；
- 联系人编号；
- 轮次编号；
- 同轮顺序；
- 创建时间；
- 附件数组。

规则：

- 默认按时间和同轮顺序稳定排列；
- 分页不得漏项或重复；
- 只返回指定联系人历史；
- 已知但暂无消息的联系人返回空列表；
- 未知联系人返回明确错误。

#### PRD-APP-008：三类路由

发送目标可以是：

1. 内置 Agent；
2. 通过回调接收消息的外部 Agent；
3. 通过待领取队列接收消息的外部 Agent。

App 不需要理解三类目标的内部处理方式，但响应中的路由状态必须可诊断。

### 10.4 图片与贴纸

#### PRD-APP-009：图片上传

- 接受 `multipart/form-data`；
- P0 仅支持 `image/*`；
- 单个文件最大 10 MB；
- 空文件或不支持类型拒绝；
- 上传成功返回附件编号、类型、MIME、文件名、大小、下载地址和创建时间；
- 下载需要鉴权；
- 下载响应使用正确 MIME；
- 文件名不能影响服务端存储路径；
- 孤立附件应按保留策略清理。

#### PRD-APP-010：消息附件

- P0 每条消息最多一个图片或贴纸附件；
- 附件必须先上传或属于支持的贴纸目录；
- 消息只能引用当前用户可访问的附件；
- 重复发送消息时不重复创建附件关系；
- 历史和幂等响应中的附件字段一致。

#### PRD-APP-011：贴纸

- 使用稳定贴纸 ID；
- 未知贴纸 ID 拒绝；
- 返回展示所需的 ID、资源引用和可选描述；
- 贴纸与图片使用统一附件数组表达；
- 贴纸目录可以扩展，但已发布 ID 不应随意改变含义。

### 10.5 Phone Context

#### PRD-APP-012：产品目的

Phone Context 用于让 Agent 在获得授权后理解有限的手机状态，例如：

- 设备是否在线；
- App 是否在前台；
- 当前打开的 AsPocket 页面；
- 当前选择的联系人；
- 最近一次状态更新时间。

它不是远程监控功能，也不是读取手机完整内容的入口。

#### PRD-APP-013：快照上传

快照至少包含：

- 快照编号；
- 快照类型；
- 产生时间；
- 上传原因；
- 状态载荷。

规则：

- 同一快照编号重复上传返回相同结果；
- 产生时间不可明显超前；
- 过旧快照按规则拒绝或标记；
- 上传原因必须来自允许集合；
- 状态字段必须符合允许范围；
- 成功响应明确包含 `accepted: true`。

#### PRD-APP-014：最新快照

- 可按类型读取最新快照；
- 调用方可以指定最大有效年龄；
- 返回快照年龄和是否过期；
- 没有数据时返回 `available: false`；
- 过期数据不得伪装为当前状态；
- Agent 使用时必须知道数据可能不是实时值。

#### PRD-APP-015：隐私边界

P0 不收集：

- 屏幕截图；
- 输入内容；
- 通知正文；
- 剪贴板；
- 短信；
- 通讯录；
- 精确定位；
- 其他 App 的内容；
- 麦克风或摄像头数据。

新增字段前必须说明用户价值、采集时机、保留时间和关闭方式。

## 11. 外部 Agent

### PRD-EXT-001：注册

外部 Agent 注册时提供：

- 稳定 `remoteAgentId`；
- 展示名称；
- 简介；
- 会话类型；
- 回调地址或队列模式；
- 可选能力说明；
- 客户端生成的注册标识。

成功后获得：

- 会话编号；
- 当前状态；
- 心跳间隔；
- 过期规则；
- 对应联系人信息。

同一 `remoteAgentId` 可以重新注册，但同时生效的会话规则必须明确。

### PRD-EXT-002：在线状态

- 外部 Agent 定期发送心跳；
- 超过有效时间未心跳时自动视为离线；
- 主动下线立即生效；
- 管理员可以强制下线；
- 离线后不再接收新消息；
- 已有历史仍可查看；
- 重新上线后联系人 ID 不变。

### PRD-EXT-003：回调模式

- Router 把用户消息发送到已注册回调；
- 回调请求包含会话、联系人、消息、附件和轮次信息；
- 回调可以返回零条、一条或多条回复；
- 每条回复可以包含文字和支持的附件；
- 超时、非法响应和 HTTP 错误有明确状态；
- 相同轮次的回调重试不得重复写入回复。

安全要求：

- P0 只允许本机或管理员明确允许的地址；
- 禁止通过回调访问云元数据地址和不受信任内网；
- 跟随重定向后再次校验；
- 日志不记录回调中的秘密。

### PRD-EXT-004：队列模式

外部 Agent 可以：

1. 拉取待处理消息；
2. 使用投递编号确认已领取；
3. 按原 `clientMessageId` 回传一条或多条回复；
4. 对重复确认和重复回传获得幂等结果。

规则：

- 待处理消息在服务重启后仍可恢复；
- 未确认消息可以重新投递；
- 已确认消息不会无限重复出现；
- 回复只能写入属于该会话和联系人的用户消息；
- 同轮回复顺序稳定。

### PRD-EXT-005：附件

- P0 外部 Agent 可以接收图片元数据和受控下载地址；
- P0 回传支持文字和贴纸；
- 不支持的附件类型返回明确错误；
- 外部 Agent 无权下载其他用户或其他联系人的附件。

## 12. 管理后台

### 12.1 后台定位

后台是本地部署和诊断界面，不是普通用户聊天界面。它应使用用户能理解的业务语言，不要求管理员阅读日志或代码才能判断基础状态。

### PRD-ADM-001：管理员登录

- 未登录只能访问登录页和必要的存活信息；
- 登录失败不说明密码匹配了哪些部分；
- 登录会话有过期时间；
- 支持退出；
- 默认密码状态必须明显警告；
- 正式使用前要求更换默认密码；
- 高风险操作再次确认；
- 登录凭据不得通过 URL 传递。

### PRD-ADM-002：信息架构

后台至少包含：

1. 系统概览；
2. 接入渠道；
3. App 与外部 Agent；
4. 对话与人格；
5. 记忆；
6. 提醒、摘要和主动对话；
7. Agent 能力；
8. 日志与诊断；
9. 数据管理。

### PRD-ADM-003：系统概览

概览展示：

- 服务状态；
- 模型状态；
- 微信运行和可发送状态；
- App 接口状态；
- 在线外部 Agent 数；
- 下次摘要时间；
- 待处理提醒数；
- 今日主动消息使用量；
- 最近错误；
- 最近一轮上下文使用率。

状态必须使用“正常、未配置、不可用、需要操作”等可理解标签。

### PRD-ADM-004：接入渠道

管理员可以：

- 选择微信、App 或同时接收；
- 扫码连接微信；
- 启停微信桥接；
- 查看最近联系人；
- 查看最近收发时间；
- 查看渠道错误；
- 知道当前是否具备主动发送条件。

切换接入方式前应说明影响，避免无意中使在线会话下线。

### PRD-ADM-005：App 与外部 Agent

管理员可以：

- 查看全部外部 Agent 会话；
- 查看联系人、类型、在线状态、最后心跳和回调地址；
- 强制某个会话下线；
- 查看最新 Phone Context 及年龄；
- 查看附件元数据；
- 不直接展示附件的服务端真实路径。

### PRD-ADM-006：对话与人格

管理员可以：

- 查看当前人格文件和内容；
- 替换或编辑人格；
- 查看最近一轮上下文使用量；
- 向当前可发送联系人手动发送一条或多条消息；
- 手动触发每日摘要；
- 清理对话和长期记忆；
- 在清理前看到保留项。

手动发送必须遵守与 Agent 发送相同的输出保护和投递规则。

### PRD-ADM-007：记忆管理

管理员可以：

- 查看记忆列表；
- 查看文件或主题内容；
- 查看更新时间、大小和格式警告；
- 删除指定记忆；
- 刷新诊断；
- 知道删除是否成功。

### PRD-ADM-008：调度管理

管理员可以：

- 查看摘要计划和最近历史；
- 查看提醒列表及状态；
- 查看主动对话开关、频率、每日上限和今日用量；
- 查看安静时段；
- 识别调度服务是否运行；
- 对失败任务获得原因和处理建议。

### PRD-ADM-009：能力状态

每项能力展示：

- 产品名称；
- 用途；
- 是否启用；
- 依赖是否已配置；
- 当前是否可用；
- 最近检查时间；
- 不可用原因；
- 是否会产生外部写入。

后台不必展示内部工具数量。

### PRD-ADM-010：日志

管理员可以：

- 查看最近日志；
- 按级别筛选；
- 按关键字搜索；
- 查看时间、轮次编号和错误摘要；
- 控制返回数量；
- 复制脱敏诊断信息。

默认不展示：

- 密钥；
- 完整令牌；
- 管理员密码；
- 未脱敏用户敏感内容；
- 模型内部思考全文。

### PRD-ADM-011：数据操作

高风险数据操作必须：

- 明确目标；
- 列出将删除和保留的数据；
- 二次确认；
- 防止重复提交；
- 返回每类数据的处理数量；
- 在失败时说明是否已完成部分操作。

人格文件、微信绑定、附件和对话数据必须是不同的清理范围，不能使用一个模糊的“全部删除”混在一起。

## 13. 数据与隐私

### 13.1 业务数据分类

| 数据 | 用途 | 用户可管理 | 默认保留原则 |
|---|---|---|---|
| 用户与渠道绑定 | 识别用户、渠道投递 | 可解除 | 持续到解除 |
| 会话与消息 | 连续聊天、历史展示 | 可清理 | 按配置 |
| 轮次与投递结果 | 幂等、诊断 | 管理员可清理 | 按配置 |
| 每日摘要 | 跨天接续 | 可查看、可清理 | 按配置 |
| 长期记忆 | 个性化交流 | 可查看、可删除 | 直到删除 |
| 提醒 | 定时投递 | 可查询、可取消 | 终态后按配置 |
| 外部 Agent 会话 | 联系人在线状态 | 可下线 | 会话过期后清理 |
| App 消息 | App 历史 | 可清理 | 按配置 |
| 附件 | 图片展示 | 可清理 | 按引用和时间 |
| Phone Context | 短期状态理解 | 可关闭、可清理 | 短期 |
| 配置 | 服务运行 | 管理员可修改 | 持续 |
| 人格 Markdown | 交流风格 | 可替换 | 独立文件 |
| 日志 | 故障诊断 | 管理员可轮转 | 短期 |

### PRD-DATA-001：数据完整性

- 消息必须属于有效会话；
- Agent 回复必须关联原用户轮次；
- 附件引用必须指向有效附件；
- 投递记录必须关联用户可见消息；
- 提醒必须属于明确用户；
- 外部 Agent 回复必须属于对应联系人；
- 删除操作不得留下会被继续读取的失效引用。

### PRD-DATA-002：数据升级

- 版本升级不得以删除业务数据作为默认手段；
- 升级前可以检查可用空间和数据一致性；
- 升级失败时不得在不说明的情况下继续运行；
- 必须提供备份和恢复说明；
- 升级完成后能够验证消息、记忆、提醒和绑定数量；
- 人格 Markdown 文件可以由用户直接复制，不纳入强制数据导入流程。

### PRD-DATA-003：保留与清理

管理员应能够配置或执行：

- 日志轮转；
- 孤立附件清理；
- 过期 Phone Context 清理；
- 终态提醒清理；
- 过期外部 Agent 会话清理；
- 对话和摘要清理；
- 长期记忆单项删除。

清理任务不得删除仍被消息引用的附件或仍待执行的提醒。

### PRD-DATA-004：隐私最小化

- 只收集实现功能所需数据；
- Phone Context 默认短期保存；
- 管理接口默认脱敏；
- 外部网页内容不与用户秘密拼接发送；
- 第三方能力只获得完成请求所需字段；
- 用户可以关闭联网能力、主动对话和 Phone Context；
- 管理员可以查看数据保存位置和清理方式。

## 14. 安全需求

### NFR-SEC-001：秘密管理

- 模型密钥、天气密钥、搜索密钥、Microsoft 授权令牌和微信凭据不得写入人格文件；
- 普通配置查询不返回秘密原文；
- 日志不得记录秘密；
- 错误信息不得包含请求头中的认证值；
- 密钥缺失时明确显示“未配置”；
- 密钥轮换后无需清理业务数据。

### NFR-SEC-002：输入安全

- 所有接口执行类型、长度、枚举和格式校验；
- 文件上传校验大小和 MIME；
- 文件名不能控制保存路径；
- URL 输入防止访问本机、私网和云元数据地址；
- Markdown 和日志展示防止脚本注入；
- 路径参数不能跳出允许范围；
- 超大正文应在完整解析前拒绝。

### NFR-SEC-003：模型权限

- 模型只能使用本轮允许的能力；
- 模型伪造不存在的能力时拒绝；
- 普通聊天不能安排不受控的主动任务；
- 网页、记忆和用户输入均不能提升模型权限；
- 高副作用动作必须符合用户意图；
- 内部思考不发送给用户。

### NFR-SEC-004：管理员安全

- 管理后台使用独立认证；
- 登录会话会过期；
- 生产使用时禁止默认密码；
- 高风险操作二次确认；
- 管理员接口与 App 接口凭据分离；
- 认证失败有频率保护；
- Cookie 使用合适的安全属性。

## 15. 可靠性、性能与可观测

### NFR-REL-001：启动

启动时分别检查：

- 基础配置；
- 数据可读写；
- 模型配置；
- 调度服务；
- 微信配置；
- 可选能力依赖。

基础聊天所需条件不满足时，服务应显示“未就绪”。可选能力缺失时，服务仍可启动，但后台明确显示受影响功能。

### NFR-REL-002：关闭

正常关闭时：

- 停止接收新轮次；
- 等待或安全结束进行中的轮次；
- 停止微信接收；
- 保存必要状态；
- 停止调度；
- 关闭外部连接；
- 不把正常取消记录成系统崩溃。

### NFR-REL-003：恢复

异常退出后应恢复：

- 未完成提醒；
- 必要的待投递消息；
- 会话历史；
- 外部 Agent 在线状态的过期判断；
- 附件元数据；
- 幂等结果。

无法自动恢复的内容必须出现在管理后台，而不是静默丢失。

### NFR-PERF-001：交互性能

| 场景 | 目标 |
|---|---|
| 健康接口 | P95 < 200 ms |
| 管理列表接口 | P95 < 500 ms，不含外部依赖 |
| App 消息历史 | P95 < 500 ms |
| 图片上传 | 在局域网 10 MB 文件可稳定完成 |
| 普通对话 | 受模型影响，必须有明确超时与进行中状态 |
| 外部 Agent 回调 | 超时可配置，默认不超过 App 可接受等待时间 |

### NFR-OBS-001：关联信息

一次请求应能关联：

- 请求编号；
- 用户；
- 会话；
- 轮次；
- 能力调用；
- 用户可见消息；
- 渠道投递；
- 提醒或外部 Agent 会话。

管理员无需接触模型内部思考，也能判断失败发生在哪个环节。

### NFR-OBS-002：关键事件

至少记录：

- 服务启动和关闭；
- 登录成功与失败；
- 渠道连接变化；
- 轮次开始与结束；
- 能力成功、失败和超时；
- 消息投递结果；
- 提醒创建、取消和触发；
- 摘要生成；
- 外部 Agent 注册、心跳过期和下线；
- 数据清理；
- 输出保护触发。

### NFR-OBS-003：指标

至少统计：

- 轮次数和失败率；
- 首条回复耗时；
- 能力调用次数和失败率；
- 消息投递成功率；
- 提醒准时率；
- 重复请求命中次数；
- 上下文使用率；
- 在线外部 Agent 数；
- 待处理消息数；
- 今日主动消息次数。

- 维护脚本必须说明影响范围，禁止把日常业务逻辑藏在脚本中；
- 管理后台前端与服务端业务规则分离；
- 文档目录只保存仍然有效的产品、接口、决策和运维说明。

## 17. 接口范围

详细字段、状态码、示例和错误码见配套接口文档。P0 接口域包括：

| 接口域 | 主要能力 |
|---|---|
| 健康与就绪 | 判断服务存活、基础能力是否就绪 |
| HTTP 对话 | 发起一轮普通聊天并查询结果 |
| App Profile | 获取内置 Agent 展示资料 |
| App 联系人 | 获取可添加联系人 |

| Phone Context | 上传快照、读取最新有效状态 |
| 外部 Agent 会话 | 注册、心跳、下线、查询 |
| 外部 Agent 队列 | 拉取、确认、回传回复 |
| 管理认证 | 登录、状态、退出 |
| 管理概览 | 配置摘要、状态与上下文使用 |
| 人格与设置 | 查看、验证和保存 |
| 微信 | 扫码、连接状态、启停 |
| 记忆 | 列表、查看、删除 |
| 调度 | 提醒、摘要、主动对话状态 |
| 能力 | 可用状态和依赖诊断 |
| 日志 | 筛选和读取脱敏日志 |
| 数据维护 | 清理对话、记忆和其他指定范围 |

### PRD-G-008：接口一致性

- 接口统一使用 JSON，文件下载和上传除外；
- 字段命名使用 `camelCase`；
- 时间使用带时区 ISO 8601；
- 列表接口使用统一分页结构；
- 错误使用统一错误对象；
- 写接口接受幂等键；
- 首次请求和幂等重放返回相同业务结构；
- 不在 200 响应中隐藏业务失败；
- 未认证优先返回 401；
- 权限不足返回 403；
- 不存在返回 404；
- 冲突返回 409；
- 输入错误返回 400 或 422；
- 依赖不可用返回 503。

## 21. 最终产品判断

Goal Chat Agent 的完成标准不是“把某个仓库的文件重新组织一遍”，而是：

- 用户可以长期、连续地与一个由 Markdown 文件定义的人格交流；
- Agent 能真正完成查询、记忆、待办和提醒；
- 微信、App、HTTP 和外部 Agent 的消息不会重复或串线；
- 用户对记忆、主动联系和隐私具有控制权；
- 管理员能够部署、配置、诊断和恢复服务；
- 开发团队可以自由选择内部结构，而产品能力和接口行为有明确验收依据。
